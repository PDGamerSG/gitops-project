    02 / What is included

    One project. Every layer accounted for.

    The repository is structured so each part of the release can be inspected, rebuilt, and exercised from one command surface.

    01 / APP

    Node runtime

    Zero-dependency HTTP service, health probes, todo API, release metadata, and an accessibility-minded interface.

    02 / BUILD

    Tested image

    Multi-stage Docker build runs the Node test suite before the runtime layer can be produced.

    03 / CLUSTER

    Kind + ArgoCD

    Three replicas, rolling updates, readiness checks, automatic sync, prune, and self-heal.

    04 / SOURCE

    Git as control

    Developer commits update the config repository; the controller pulls the desired state into the cluster.

    03 / The release path

    Commit to cluster without a kubectl shortcut.

    The CI side writes Git. ArgoCD owns the pull phase. That separation makes the result auditable and reversible.

    01

    Developer push

    Version change lands in the source repository.

    02

    Tests + build

    Unit tests run inside the image build.

    03

    Registry

    Immutable commit SHA image is pushed.

    04

    Config Git

    Desired image tag is committed to manifests.

    05

    ArgoCD

    Cluster converges and heals drift automatically.
